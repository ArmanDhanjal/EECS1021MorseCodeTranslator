Issue 1 --> LED Blinks Out of Sync

To diagnose issue, print statements were added in sections to confirm where the issue begins.
Started with adding print statements at end to first check if main method is passing the correct arguments to the
sequence method.

Updated method with print statements:

public static void sequence(PicoController pico, String s) {

        System.out.println(s); // for testing.

        if (s.equals(" ")) {
            pico.ledOff();
            pico.sleep(BETWEEN_WORDS);
        }
        else {
            for (int i = 0; i < s.length(); i++) {
                char currentSymbol = s.charAt(i);

                System.out.println(currentSymbol); // for testing.

                if (currentSymbol == '.') {
                    shortBlink(pico);
                }
                else if (currentSymbol == '-') {
                    longBlink(pico);
                }
            }
            pico.sleep(BETWEEN_CHARACTERS);
        }
    }

After analyzing the output, it was determined that there was no logical error up to this section of the program.
-----------------------------------

Solution: It was concluded that the source of error was that the Pico and Java program was out of sync. Initially,
          the program utilized the Pico's hardware timer to control the onboard LED. When the command pico.sleep()
          was executed, it caused the main Java program thread to pause while the hardware would continue to run
          independently. This latency led to the software and hardware falling out of sync, leaving the LED to
          blink at incorrect intervals.

          To solve this issue, the use of the Pico's hardware timer was removed. Both the shortBlink() and
          longBlink() methods were changed to the following (please review commit dad9a79 for previous code):

    public static void shortBlink(PicoController pico){
        pico.ledOn();
        pico.sleep(DOT_TIME);

        pico.ledOff();
        pico.sleep(BETWEEN_ELEMENTS);
    }

    public static void longBlink(PicoController pico){
        pico.ledOn();
        pico.sleep(DASH_TIME);

        pico.ledOff();
        pico.sleep(BETWEEN_ELEMENTS);
    }
}

Once changes were made, the Pico and software were able to run in sync and produce the correct morse code message.
The added print statements in the sequence method was kept to ensure the written output (which was translated by
hand to ensure accuracy) matched with the blinks produced by the Pico LED. No other issues were found during
testing.

Issue 2 --> Continuation Rigidity

In this code, when prompting the user to see if they would like to continue, the application only accepted "y"
and "n" as valid inputs. This section of code was changed so that it will now accept the same inputs regardless
of capitalization.

In order to follow the same method of cleaning the inputs, the method cleanInput() was altered so that it returns
a string variable rather than a character array. The following is the new method (please see commit 88e19bf to
see previous iteration).

  private static String cleanInput(String s){
        return s.toLowerCase().trim();
    }

The following line in the main method, where the user's message is being translated into a character array (line
42) was changed to the following:

char[] cleanMessage = (cleanInput(message)).toCharArray();


Issue 3 --> Changing Access Modifiers

In all previous iterations of TextToMorse, the method access modifiers used were public. To ensure better data
safety, these access modifiers were changed to private so that other applications cannot access these methods.

When testing, no issues were found.
